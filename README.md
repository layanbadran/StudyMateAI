# StudyMate AI

Upload your own PDF lecture notes, then ask questions about them. Answers are generated by
Claude **only from your documents**, with the file name and page number shown as sources.

## Architecture

```
Browser (React + TypeScript + Tailwind)
   │  upload PDF / ask question   (X-Session-ID header = private user space)
   ▼
FastAPI backend (Python)
   ├─ pdf_service   PyMuPDF: text per page
   ├─ chunking      overlapping pieces, each keeps its page number
   ├─ embeddings    sentence-transformers: text → vector
   ├─ vector_store  ChromaDB: one collection per user session
   ├─ rag           the pipeline glue
   └─ llm           Anthropic Claude API (the key lives only on the server)
```

## How the RAG pipeline works

**RAG = Retrieval-Augmented Generation.** Claude doesn't know your notes, so we first
*retrieve* the relevant passages and then *give them to Claude* together with the question.

**When you upload a PDF (indexing)**
1. **Validate**: the extension is `.pdf`, the size is under the limit, and the file really starts with `%PDF-`.
2. **Extract**: PyMuPDF reads the text of each page. PDFs without text (scans) are rejected with a clear message.
3. **Chunk**: each page is split into ~1000-character pieces with 200 characters of overlap, cutting at sentence ends when possible. Chunks never cross pages, so every chunk has one exact page number.
4. **Embed**: the sentence-transformers model turns each chunk into a vector (numbers that capture meaning).
5. **Store**: vectors + chunk text + `filename` + `page` go into ChromaDB. **The PDF file itself is never saved.**

**When you ask a question (retrieval + generation)**
1. The question is embedded with the same model.
2. ChromaDB returns the `TOP_K` closest chunks (cosine distance).
3. Chunks farther than `MAX_DISTANCE` are dropped. If none are left, the app says there isn't enough information and **does not call Claude**.
4. The remaining chunks are numbered `[1]..[n]` and placed in the prompt. The system prompt tells Claude to use only them, cite `[n]`, ignore instructions hidden inside documents, and reply `INSUFFICIENT_CONTEXT` if they don't answer the question.
5. The UI shows the sources Claude cited (file, page, excerpt) under the answer.

**Privacy / isolation:** each browser gets a random session ID and its own ChromaDB collection.
This keeps users apart but is **not a login system**. Add real authentication before putting
this on the public internet.

## Setup

You need **Python 3.10+**, **Node.js 18+**, and an **Anthropic API key** (https://console.anthropic.com).

### 1. Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Windows: copy .env.example .env
# open .env and paste your key after ANTHROPIC_API_KEY=
uvicorn app.main:app --reload --port 8000
```

The first upload downloads the embedding model (~470 MB), so it is slow once.
Check the server: open http://localhost:8000/api/health

### 2. Frontend (in a second terminal)

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173

### 3. Tests (optional)

```bash
cd backend
pytest
```

The tests use a fake embedder and a fake Claude, so they run offline. They check the pipeline
wiring, not answer quality.

## Settings (backend/.env)

See `.env.example`. The ones you may want to change: `ANTHROPIC_MODEL`, `EMBEDDING_MODEL`,
`MAX_UPLOAD_MB`, `CHUNK_SIZE`, `CHUNK_OVERLAP`, `TOP_K`, `MAX_DISTANCE`.

## Troubleshooting

| Problem | Fix |
|---|---|
| Banner "Answers are turned off" | `ANTHROPIC_API_KEY` is empty in `backend/.env`. Add it and restart the backend. |
| "Can't reach the StudyMate server" | The backend isn't running on port 8000. |
| "Embedding model could not be loaded" | Check your internet on first start and your free disk space. |
| Good questions get "not found in your documents" | Raise `MAX_DISTANCE` (e.g. 1.0) or `TOP_K`. |
| Unrelated questions still get answers | Lower `MAX_DISTANCE` (e.g. 0.7). |
| "No selectable text" | The PDF is scanned images. OCR isn't supported yet. |

## Known limits of this MVP

- No OCR for scanned PDFs.
- No real user accounts (see the isolation note).
- Each question is answered on its own, with no follow-up memory.
- Tables and formulas in PDFs may extract poorly.
